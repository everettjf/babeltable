# BabelTable 最终产品规划

> 版本：1.0 · 2026-08-24  
> 状态：原始范围规划。2026-09-22 收尾发现并修复额外可靠性问题，当前验收状态以 [App Store 收尾清单](APP_STORE_CLOSEOUT.md) 为准；下文完成度与测试记录均为历史记录。

## 1. 最终产品定义

> **BabelTable 使用 OpenAI 进行实时双向翻译，并把系统翻译不会长期保留的双语对话保存下来，方便以后查看、学习和复习。**

它是一个个人使用的小工具，不是翻译平台。

产品价值只有两层：

1. 对话时，帮助两个人实时理解对方。
2. 对话后，保留双方说过的原文和译文。

宣传语可以直接使用：

> **边聊边翻译，聊完还能回看。**

## 2. 永久边界

### 产品固定选择

- 只使用 OpenAI `gpt-realtime-translate`。
- 用户自行提供 OpenAI API Key。
- API Key 保存在 iOS Keychain。
- 对话记录默认只保存在本机。
- 不运营开发者后端。
- 不做账户和订阅。
- 只做 iPhone/iPad 原生 App。

### 明确不做

- 不接入 Google、Apple、DeepL 或其他模型。
- 不做模型选择、质量比较和自动路由。
- 不做云端翻译服务。
- 不做多人会议或企业管理。
- 不做相机、图片、文档和网页翻译。
- 不做复杂的课程、背单词或 AI 教师系统。
- 不为了“功能完整”增加与保存对话无关的能力。

将来出现新想法时，只问一个问题：

> 它是否让真实对话保存得更可靠，或者保存后更容易使用？

答案是否定的，就不进入产品。

### 辅助能力

以下能力已经存在，但不是产品成立的必要条件：

- 实时译文二次润色。
- 上下文一致性。
- 正式/随意语气。
- 用户术语表。
- 近场/桌面远场麦克风配置。
- 自动音量平衡。
- 诊断日志与分享。
- 会话中分享当前字幕。

### 尚未完成，但不阻止 1.0 的功能

- 历史全文搜索。
- 自定义会话标题。
- 收藏某一句对话。
- 专门的复习卡片。
- App 界面本地化。

这些只能由实际使用需求触发，不应在发布前继续扩张。

## 4. 结论：产品已经完成到什么程度

按最终定义判断：

- 实时翻译：完成。
- 自动保存：完成。
- 本地查看：完成。
- 删除和导出：完成。
- 异常保护机制：代码已完成，仍需验证。

因此，**1.0 规划内的开发完成度为 100%**。剩余事项属于发布前人工验收，不再包含待开发功能。

剩余工作不是继续设计功能，而是证明以下事情在真实设备上可靠：

1. 长对话不会丢轮次。
2. 停止后只生成一份历史，不重复。
3. 来电、后台、断网和重连后记录仍可打开。
4. 导出的内容与屏幕内容一致。
5. 删除后文件确实消失。

## 5. 1.0 范围锁定

### 1.0 必须包含

- 当前双向实时翻译。
- 面对面和聊天两种显示方式。
- 自动保存本地历史。
- 历史详情、删除、分享。
- API Key、用量估算和诊断。
- 当前的可靠性处理。

### 1.0 发布前只允许做

- 修复会导致翻译失败、记录丢失、重复或无法打开的缺陷。
- 补充保存与恢复测试。
- 修复隐私说明、README 或 App Store 描述中的事实错误。
- 修复明显的崩溃、布局遮挡和无障碍问题。

### 1.0 发布前禁止加入

- 搜索、收藏、复习系统。
- 新模型或新服务商。
- 云同步和账号。
- 自动摘要和复杂学习能力。
- 与核心保存闭环无关的新设置。

范围锁定的目的是先让真实使用证明“保存对话”是否足够有价值。

## 6. 发布前唯一工程任务：保存可靠性验证

当前最大证据缺口是 `SessionStore` 和草稿保存没有直接单元测试。现有测试主要覆盖错误分类、重连、音频中断和语言切换。

### 应补的自动化测试

1. **保存并读取**
   - 保存包含多个 `ChatTurn` 的会话。
   - 重新创建 Store 后能完整读取。
   - 原文、译文、语言、时间和 ID 完全一致。

2. **草稿被最终会话覆盖**
   - 使用同一 UUID 保存 `endedAt == nil` 的草稿。
   - 再保存 `endedAt != nil` 的最终会话。
   - 文件和内存列表都只有一条。

3. **重复保存不重复**
   - 同一会话保存多次。
   - `sessions` 中始终只有一个 ID。

4. **删除彻底**
   - 删除后内存列表为空。
   - 重新创建 Store 后也不会重新出现。

5. **旧数据兼容**
   - 缺少 `chatTurns` 或 `refinedText` 的旧 JSON 能正常解码。

6. **损坏文件隔离**
   - 一个损坏 JSON 不影响其他正常会话读取。

为便于测试，`SessionStore` 应允许注入存储目录，而不是在测试中写真实 Documents 目录。

## 7. 真机验收清单

语音和音频路由必须使用真实 iPhone 验证。

### 基础对话

- [ ] 英语与中文双方各说至少 10 轮。
- [ ] 聊天模式中每轮原文和译文归属正确。
- [ ] 面对面模式双方都能正确阅读自己的面板。
- [ ] 点击停止后出现“Session saved”。
- [ ] 历史中只有一条新会话。
- [ ] 详情中的轮次数、顺序和内容与刚才一致。

### 长对话

- [ ] 连续运行 30 分钟。
- [ ] 至少产生 50 个轮次。
- [ ] UI 没有明显卡顿。
- [ ] 停止后历史能打开。
- [ ] 导出文件包含全部已完成轮次。

### 生命周期

- [ ] 对话中切到后台，再返回前台继续。
- [ ] 锁屏后重新进入 App。
- [ ] 来电或 Siri 中断后恢复。
- [ ] 每种情况下草稿不会丢失或产生重复会话。

### 网络

- [ ] Wi-Fi 切换蜂窝网络。
- [ ] 短暂断网后恢复。
- [ ] 持续断网超过最大重试次数。
- [ ] 已完成轮次仍保存在历史中。

### 音频路由

- [ ] 手机内置麦克风与扬声器。
- [ ] 有线或 USB-C 音频设备（如可用）。
- [ ] 蓝牙耳机连接、断开与重新连接。
- [ ] 路由变化后不会崩溃或保存重复记录。

### 历史管理

- [ ] 分享 `.txt` 后使用 Files/Notes 打开，内容和 Unicode 正常。
- [ ] 删除一条历史后重新启动 App，记录不会回来。
- [ ] 多次进入和退出历史页面不会改变内容。

## 8. 发布判定标准

以下条件全部满足即可发布 1.0：

- 自动化测试全部通过。
- 30 分钟真机会话完成并正确保存。
- 后台、来电、断网三类中断各验证一次。
- 没有已知的记录丢失、重复或损坏问题。
- README、隐私政策和 App Store 描述与实际数据流一致。
- API Key、音频和对话正文没有进入诊断日志。

不需要等待搜索、收藏或复习功能。

## 9. 发布后的唯一决策门

先连续真实使用 2–4 周，只记录三个问题：

1. 保存的会话是否会再次打开？
2. 历史变多后，是否真的找不到需要的内容？
3. 是否真的会挑出某些句子反复学习？

对应决策：

| 实际现象 | 下一步 |
|---|---|
| 很少再次打开历史 | 不增加功能，重新判断产品价值 |
| 经常打开，但找不到内容 | 只做全文搜索和标题 |
| 经常复制某些句子学习 | 只做收藏句子 |
| 收藏后仍反复手动查看 | 再做最简单的复习卡片 |
| 当前历史已经够用 | 保持产品不变，只维护兼容性 |

功能必须由行为触发，不能由规划本身触发。

## 10. 可选功能的最小顺序

如果自用确实产生需求，严格按以下顺序，每次只做一项：

1. **全文搜索**：本地过滤原文与译文。
2. **会话标题**：允许用户重命名，不做 AI 自动标题。
3. **收藏句子**：给 `ChatTurn` 增加收藏状态。
4. **简单复习**：看一边、揭晓另一边、“记住/没记住”。

不提前设计完整学习系统。

## 最终执行结论

BabelTable 的规划已经收口：

> **当前功能就是 1.0。停止增加功能，补齐保存测试，完成真机长对话和中断验收，然后发布并真实自用。**

后续是否增加搜索、收藏和复习，只由实际保存记录后的使用行为决定。
